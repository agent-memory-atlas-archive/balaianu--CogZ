During Phase 5 implementation, the hybrid search integration test
expected entity `u1` to rank first, but it didn't.

**Root cause:** The deterministic mock embedding model hashes the
complete input string. The test's query embedding used a query
string that didn't exactly match the text used to embed the entity.

The search implementation embeds entities using
`format!("{}\n\n{}", title, content)`. The test query embedding
used a different concatenation, producing a different vector. RRF
fusion then ranked the entity lower because the vector distance
was large.

**Fix:** Changed the test query vector to use the exact
`"title\n\ncontent"` format the search implementation uses.

**Lesson:** When using deterministic mock embeddings, the query
embedding text must exactly match the entity embedding text
format. This is a test coupling issue, not a production issue —
real embedding models are semantically robust to formatting
differences.
