Found during a full-repo audit (commit 386e131): deliveries/entity_usage rows were written with SQL datetime('now') ('YYYY-MM-DD HH:MM:SS') while events/entities use chrono to_rfc3339() ('T' separator). String comparisons across the formats misordered same-day rows in BOTH directions: ' ' < 'T' made sweep_old_telemetry delete boundary-day deliveries still inside retention and never_delivered_since report delivered entities as dead weight; 'T' > ' ' made mining windows and the nudge suppress window over-include stale events.

Fixed by wrapping both sides of every created_at comparison in datetime() (format-agnostic, also heals pre-existing mixed rows — no migration) and unifying writes to RFC3339.

Detection gotcha: existing tests masked the bug because they backdated rows with datetime('now', ...) — matching the cutoff format, not the production write format. Boundary-day regression tests now seed at an adaptive same-date offset so the separator decides the compare regardless of wall-clock time.

Files: src/storage/usage.rs (writes + sweep + never_delivered_since), src/storage/mining_signals.rs (5 window sites), src/hooks/nudge.rs (suppress window).
