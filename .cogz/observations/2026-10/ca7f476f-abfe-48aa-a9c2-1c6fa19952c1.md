Dead-weight sweep after the NLI-verify removal surfaced three
mechanical fixes, all landed:

1. `sync_all` (full `cogz index`) forced every unchanged file entity
   through the update+embed path — the content-hash skip only ran on
   the incremental side. Skip is now unconditional (file hash covers
   frontmatter+body; all status mutations are file-first, so a
   same-hash file cannot diverge in declared state). Live: 165
   skipped / 0 updated / 0 re-embedded, vs ~163 forced updates before.

2. The skip unmasked a latent gap: nothing healed entities whose
   embedding was never written (model down at index, interrupted
   embed-bg, dropped vec rows). `ids_missing_embeddings(conn, space)`
   now unions them into the embed set — active-only, so the heal set
   is exactly "what default search must be able to return."

3. Stale embedding semantics made coherent: a vector lives iff its
   described content still exists. `mark_code_entities_stale_*` drop
   code_embeddings on the mark (content vanished; reappearing code
   re-embeds via sync); `mark_deleted_as_stale` drops knowledge
   vectors the same way; flagged-stale entities with live files keep
   theirs. reindex_equiv's "dead weight" note is gone — embeddings
   now match rebuild exactly (2515 vectors = 2515 active entities).

4. drift.rs split four ways (drift/refstate/post_index/verify, all
   <400 lines) with a shared drift_test_support module; the
   triplicated resolve_file_path is deduped to refstate.

Also: `run_suite.py` now waits out spawned embed-bg processes between
timing arms (checked via /proc comm+argv — `pgrep -f` self-matches
shell wrappers) and records embedding completeness in timing.json.
