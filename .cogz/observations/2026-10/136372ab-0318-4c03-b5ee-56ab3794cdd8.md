Measured on the real dogfood corpus: CodeRankEmbed-onnx-int8 produces different embeddings for the same text depending on batch composition AND batch size (0.955 mixed-length, ~0.968 vs batch≥2, up to 0.909 worst-case on 384 real code entities). The drift is the batch dimension itself, not padding — length-grouped batching does not restore solo vectors. bge-base is batch-invariant (0.999999 at every size). Since embed_query always runs batch=1, batched document vectors are systematically off-canonical vs queries. Solo inference is both canonical and faster on measured corpora (170s vs 282s for 384 code entities — entities truncate at 512 so every batch runs max-size attention). Fix: ModelType::Code embeds per-text in OnnxEmbeddingModel::embed.
