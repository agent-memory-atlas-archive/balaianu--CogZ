Two findings from the full canonical battery (4 corpora, A1-A3 + B
landed, code embeddings normalized solo):

1. Lexically-disjoint queries are the coverage gate's false-silence
   class. 12/150 commit-GT queries silenced; only 5 had real top-6
   hits ungated (~3% true recall loss — the other 7 scored 0 anyway,
   so silence there is honest). Signature case: commit subjects
   ("Upgrade to syn v3") share no vocabulary with the files they
   touched. No relevance threshold separates them from negatives
   (negatives hit top-1 relevance 0.5-0.8 too). This is an
   answerability-verification problem — query-vs-head entailment —
   distinct from item 96's claim-vs-code NLI but able to reuse the
   same model machinery. Logged as backlog item 99.

2. Benchmark searches were perturbing the corpus they measured.
   run.py searches recorded access_count bumps; expansion scoring
   consumes access_count, so consecutive benchmark runs ranked
   expanded tails differently — clap commit R@20 moved 0.39->0.57
   between baselines with byte-identical direct results. The
   record:false flag now exists precisely for this; run.py and
   pack_metrics.py pass it on search and get_context. Agent-replay
   deliberately keeps record=true (access bumps are its signal).
   Any benchmark diff that includes expanded-tail behavior must
   check telemetry state before attributing to code changes.
