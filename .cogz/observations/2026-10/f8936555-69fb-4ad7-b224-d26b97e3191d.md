The v0.5.0 release Windows leg failed on `error[E0658]: use of unstable library feature windows_by_handle` — `MetadataExt::volume_serial_number()`/`file_index()` used in repo_cache.rs `file_identity` are still unstable APIs (rust#63010) and cannot compile on stable Rust.

Root cause chain worth remembering: the 0.5.0 pre-release audit verified the Windows file-identity *logic* (volume serial + file index semantics, cfg gating structure) but never compiled the cfg(windows) branch — host tests and clippy never see cfg'd code for other platforms. CI caught it at release time, which is the correct safety net but the worst possible moment.

Fix: `GetFileInformationByHandle` on an opened File handle via windows-sys 0.59 (already in the dep tree transitively — zero new packages). Committed as 77d1948; tag v0.5.0 was force-moved to the fix commit after deleting the partial release.

Secondary consequence: the failed leg skipped the `checksums` job entirely (needs: all matrix legs) so the release published without SHA256SUMS.
