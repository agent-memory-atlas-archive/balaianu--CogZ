Hit during real reindex: `table cochange has no column named entity_id`. The repo DB was indexed during the intermediate file-level iteration of migrate_v7 (columns term/file_path/commit_id), then the migration was edited in place to entity-grained (term/entity_id/commit_id) without a version bump. `CREATE TABLE IF NOT EXISTS` never heals an existing table's shape, and user_version was already 7, so the migration never re-ran — `sync_cochange` failed on every index thereafter.

Recovery: `cogz reset` + `cogz index` (the designed path — DB is disposable). Rebuild produced 21,889 co-change rows on the repo itself.

Lesson for schema iteration: editing a migration body in place after any DB has run it leaves permanently drifted tables. During development, either bump the version for each shape change or accept that intermediate DBs need reset+index. Not worth defensive code in migrate_v7 (e.g. DROP TABLE) — the file-level shape never shipped; no released upgrade path (v6→v7, or fresh) can carry it.
