Non-training NLI fixes shipped and measured through the REAL Rust
pipeline (`examples/nli_pairs`, 184-pair corpus, bidirectional scoring):

- **Numeric gate** (`consolidate/numgate.rs`): deterministic
  numeric-slot check inside `classify_candidates`, runs before NLI —
  same slot + different canonical value ⇒ flag; equal ⇒ skip;
  ambiguous ⇒ defer. Canonicalizes time/size/% units. Also runs when
  the NLI model is unavailable (previously: zero detection). Measured:
  3 fires, 3/3 correct — identical to the Python reference.
- **Merge entailment was dead code**: old min-direction entailment ≥
  0.85 was unreachable — R≤0.04 at ANY threshold on xsmall
  (models never emit mutual P(E)≥0.85 on spec text). Changed
  `confirm_duplicate_nli` to max-direction and the default
  `dedup_nli_threshold` 0.85→0.55. Now fires: xsmall P=.76 R=.24,
  tasksource-xsmall P=.71 R=.30.
- **Contradiction channel** (bidirectional max-P(C) ≥0.70, was already
  implemented): with gate — xsmall P=.54 R=.90, tasksource P=.67 R=.68.
- **Tokenizer padding strip** in `OnnxNliModel::try_load` —
  `.with_padding(None)` removes pad-to-max configs baked into
  tokenizer.json (tasksource pads to 1680 → 5s/inference otherwise).
- Argmax acc through real pipeline: xsmall .495, tasksource-xsmall .543.

Model note: tasksource-xsmall staged at
`~/.local/share/cogz/models/sileod/deberta-v3-xsmall-tasksource-nli`
(87MB, 30ms). Better precision/accuracy but LOWER contradiction recall
at 0.70 — per-model threshold tuning needed before any swap. No
registry entry yet (HF repo has no ONNX to download).

Search suite unchanged (consolidation doesn't touch retrieval):
P@5=.171 MRR=.544 R@20=.952 p50=546ms, 32 queries, no errors.
Consolidate dry-run on real corpus: 0 merges, 0 promotions — healthy
(no near-dup observations above dedup cosine).

Remaining known issue: tasksource-xsmall has no public quantized ONNX;
the staged artifact is a local export — a swap needs a hosting/export
story first.
