mark_stale_for_removed_entities guards its DB read with `if let Ok(mut stmt) = conn.prepare(&sql) && let Ok(rows) = stmt.query_map(...)`. Any prepare/query error (SQLITE_BUSY under contention, schema drift) silently skips the chunk — renamed/removed entities stay `active` and downstream knowledge is never flagged stale. This is the worst failure mode for the core promise: stale detection fails with zero signal. Verified 2026-09-14. Backlog item 22.
