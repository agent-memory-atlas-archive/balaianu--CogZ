## CogZ v0.6.0

This release is the result of a full independent audit remediation: 85 findings
across correctness, lifecycle, packaging, search, and CI were resolved before
tagging, plus measured retrieval improvements backed by a reproducible
benchmark suite.

### Highlights

- **Audit remediation (H/M/L/P, 85 items)** — transactional migrations,
  `reset --purge` dry-run default with lock guards, bounded file-lock waits,
  single background worker per repo, duplicate-ID detection in sync and
  `cogz doctor`, secret scanning on entity files and mined tool output,
  RFC 3339 timestamp validation, and hardened installers (fail closed,
  pinned versions, shasum fallback).
- **Retrieval improvements, measured** — `split_identifiers` closes the
  camelCase FTS gap; `code_embeddings` allows opting code entities out of
  embedding; `force_fts_only` is a supported no-model switch. Improvements
  are validated by the in-repo benchmark suite across four corpora.
- **Lifecycle hardening** — status transitions validated before file writes,
  stale reactivation on file restore, and scoped reference re-sync. Entity
  statuses are working-state semantics; see `docs/design/entity-model.md`
  for the rebuild boundary.
- **Release pipeline hardening** — tag↔version check gates the release,
  tests gate binary builds, SHA256SUMS with build-provenance attestation,
  pinned MCP registry publisher, Docker image verified with a real MCP
  handshake before push to GHCR.
- **Packaging** — `--locked` Docker build as non-root, fixed Windows
  self-update, semantic version comparison in update checks.

### Upgrade notes

- Code entity hash format changed (hash v2): the first `cogz index` after
  upgrade rehashes all code entities — one-time churn, not corruption.
- `claim_entailment_threshold` and `silence_threshold` config keys were
  removed; unknown keys now produce a warning.
- `.cogz/.bg.lock` and `*.lock` under `.cogz` are ignored; prune stale
  ignores if you tracked them.
