## CogZ v0.6.3

Patch release fixing an intermittent Windows failure when two
processes open the same repository database.

### Highlights

- **Concurrent database open fixed on Windows** — `Storage::open`
  ran `PRAGMA journal_mode=WAL` unconditionally on every open, and
  the journal-mode transition takes lock access even when the
  database is already in WAL mode. `busy_timeout` was only set
  afterward, so a second process opening the same repo (two MCP
  servers, a hook firing while `embed-bg` runs) hit the lock window
  with no wait budget and failed instantly with
  `sqlite error: disk I/O error`. The timeout is now set first, and
  the journal-mode pragma is skipped entirely when the database is
  already WAL — a second open of a WAL database performs no locking
  write at all.

### Upgrade notes

- **Windows users should upgrade.** The failure was intermittent —
  it surfaced under concurrent opens, most visibly as flaky MCP
  server startup. No corruption risk; opens either succeeded or
  errored.
- No schema, file-format, or config changes — drop-in binary swap;
  existing `.cogz` data is untouched.
