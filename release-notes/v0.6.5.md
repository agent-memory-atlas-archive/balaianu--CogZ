## CogZ v0.6.5

Patch release completing the `cogz configure` PATH fix: upgrades
repair stale entries instead of skipping them, and binary paths
containing whitespace are now quoted correctly in hook commands.

### Highlights

- **Re-running `cogz configure` repairs bare-`cogz` entries in
  place.** Configs generated by ≤0.6.3 (or hand-wired with `cogz` as
  the command) still fail under hook runtimes with a minimal PATH.
  Merge dedup counted those entries as already wired, so v0.6.4's
  absolute-path generation never reached them. A post-merge upgrade
  pass now rewrites a literal `cogz` argv[0] to the resolved binary,
  preserving the entry's flags, timeout, and matcher — for hook
  commands and MCP `command` fields, in JSON and TOML (Codex) config
  alike. Other tools' commands and wrapper invocations
  (`bash -c '…'`) are untouched, and upgrading cannot create a
  duplicate entry.
- **Binary paths with whitespace are shell-quoted.** An install under
  e.g. `C:\Users\Jane Doe\…` produced an unquoted argv[0] that split
  mid-path in hook command strings. Generated commands now
  double-quote the binary when needed; MCP `command` fields keep the
  raw path (passed directly as argv[0], not shell-parsed).
- **Docs match the generator.** `agent-setup.md`, `hooks.md`, and
  `mcp-tools.md` no longer prescribe a bare `cogz` command for manual
  setups, and `cli-reference.md` documents the repair-on-reconfigure
  behavior.

### Upgrade notes

- **Just re-run `cogz configure <harness>` after upgrading.** The
  v0.6.4 note advising manual removal of bare-`cogz` entries no
  longer applies — configure now repairs them automatically,
  preserving your flags.
- **Idempotent:** a config already on absolute paths reports
  `already configured` and is left untouched.
