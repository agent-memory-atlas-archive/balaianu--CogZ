## CogZ v0.6.4

Patch release fixing `cogz configure` generating hook and MCP commands
that fail in environments where `~/.local/bin` is not on PATH.

### Highlights

- **Generated hook and MCP commands now invoke the resolved binary
  path.** Every harness emitted a bare `cogz` argv[0]. Agent hook
  runtimes and MCP spawners frequently launch with a minimal PATH
  (`~/.local/bin` absent), so the command failed with exit 127 and
  hooks silently did nothing. `configure` now resolves the running
  binary via `current_exe` and writes that path into generated hook
  commands and `mcpServers.cogz.command` for all six harnesses
  (Claude Code, Cursor, Codex, Gemini, Copilot, Devin).

### Upgrade notes

- **Re-run `cogz configure` after upgrading** if your generated config
  carries a bare `cogz` command and hooks have not been firing. Note
  that merge dedup treats `cogz` and an absolute path to it as the
  same installed hook, so existing entries are left as written —
  remove the affected `command` entries first (or edit them to the
  absolute path) if you want configure to lay down the new form.
- **No behavior change for existing installs** — the fix only changes
  what newly written config files contain.
