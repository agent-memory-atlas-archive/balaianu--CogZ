## CogZ v0.6.2

Patch release fixing a Windows-specific bug that broke every write
path in v0.6.0/v0.6.1.

### Highlights

- **Windows repo lock fixed** — `.cogz/.lock` was opened append-only;
  on Windows `LockFileEx` requires `GENERIC_READ`/`GENERIC_WRITE`, so
  every `file_lock()` failed with `Access is denied`. All write paths
  that take the lock (verify stamping, post-index heal/backfill,
  debounced sweeps, hook handlers) errored or degraded on Windows.
  The lock file now opens read+write with no truncation. Linux and
  macOS are unaffected — `flock` ignores the open mode.
- **Windows clippy clean** — `CAPTURE_TAIL_BYTES` is gated under
  `#[cfg(unix)]` to match its only uses; fixes the `-D warnings`
  failure on Windows CI.

### Upgrade notes

- **Windows users on v0.6.0/v0.6.1 should upgrade.** Writes on those
  builds failed closed — operations errored rather than proceeding
  unlocked, so there is no corruption risk, but indexing/verify
  produced no durable writes.
- No schema, file-format, or config changes — drop-in binary swap;
  existing `.cogz` data is untouched.
