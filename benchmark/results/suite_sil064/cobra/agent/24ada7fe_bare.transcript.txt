## Changes

**`completions.go`** — `InitDefaultCompletionCmd` now takes `args ...string` and no longer skips when the command has no subcommands. After building the `completion` command, it checks whether the program has any "real" subcommands — excluding the hidden `__complete` request command, which `initCompleteCmd` may have already added. If `completion` would be the only subcommand, it is removed unless:

- it's being called (`args[0] == "completion"`), or
- it's being completed itself (`__complete`/`__completeNoDesc` as `args[0]`, `completion` as `args[1]`, with a further `toComplete` arg after it — so `__complete completion` still removes it, while `__complete completion ""` keeps it).

**`command.go`** — `ExecuteC` now computes `args` (from `c.args`/`os.Args`) before the init calls and passes them to `InitDefaultCompletionCmd(args...)`, keeping `initCompleteCmd(args)` after `checkCommandGroups`.

This preserves the `__complete` machinery for root-only programs (flag/argument completion still works) while restoring their ability to accept positional arguments, per the commit description.
