## The fix

**Bug:** `reindex_incremental` in `src/index/mod.rs` called `code_graph::sync_code_edges` — a full-scan function that does `DELETE FROM edges WHERE edge_type IN ('calls','imports','extends')` globally — with only the changed-file subset. Every structural edge from unchanged files was destroyed on each incremental reindex.

**Changes:**

- `src/storage/edges.rs` — added `delete_structural_edges_by_sources(conn, source_ids)`: chunked `IN` delete scoped to `source_id` × structural edge types. Also replaced the inline `mod tests` with `mod tests;` so the pre-existing `edges/tests.rs` (superset containing the new regression test) is wired into the build.
- `src/index/code_graph/incremental.rs` (new) — `sync_code_edges_incremental`: loads **all** active code entities from the DB to build the name→UUID map (so cross-file targets into unchanged files still resolve — the second half of the bug), collects source IDs for entities belonging to changed files, deletes only their outgoing edges, then re-inserts edges parsed from the changed files' ASTs. Lock is dropped between the fetch and insert phases (fetch → drop → parse → re-acquire pattern).
- `src/index/code_graph/mod.rs` — `mod incremental;` + re-export.
- `src/index/mod.rs` — incremental path now calls `sync_code_edges_incremental`.
