## Changes

**`src/storage/crud_batch.rs`** — added `scrub_event_payloads()`, a batched `UPDATE events ... json_remove(payload, '$.old_content', '$.new_content', '$.title')` that strips entity-text keys while preserving event type, timestamp, and entity linkage. Wired into:

- `tombstone_entity_with_timestamp` — scrubs after the status-guarded UPDATE succeeds (rejected/superseded → pruned only); `entity_id` stays linked since tombstones preserve event history.
- `delete_entity_cascade` — scrubs *before* nullifying `entity_id`, since rows can't be matched to the entity afterward.
- `delete_entities_cascade_batch` — same scrub per chunk, keeping the cascade-delete invariant uniform (used by `enforce_tombstone_limit`).

**`src/files/entities.rs`** — `EntityFile::from_content` now rejects `status: pruned` files carrying a non-empty title or body (whitespace-tolerant). This is the single parse funnel for `read_entity_file` and sync's `read_and_parse`, so a contentful tombstone can't be minted through the parse path — it surfaces as a `FrontmatterError::Parse`, loud not silent. Legitimate tombstones written by `run_prune` (empty title + body) still parse and sync.
