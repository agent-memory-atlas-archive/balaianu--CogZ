## Changes — all in `src/index/sync/mod.rs`

**Added `normalize_content(content, language)`** — a single-pass scanner that strips comments before hashing:

- `//` and `/* */` for C-like languages (rust, go, javascript, typescript, tsx); `#` for python and bash
- String literals are copied verbatim so `"hello # world"` and `"not a // comment"` survive — `'` only counts as a delimiter for hash languages, since in Rust it would misparse lifetimes like `&'a str`
- For bash, `#` only starts a comment at a word boundary, so `${#x}` and `x#y` aren't mistaken for comments
- Post-pass trims trailing whitespace per line and drops blank lines; internal whitespace is deliberately preserved so real edits still register

**Wired into `convert_entities`** — the hash is now `content_hash(&normalize_content(&ce.content, language))`, with the language pulled from `ce.properties["language"]` (every extractor, including file entities, sets it). The raw `ce.content` stored in the DB is untouched — only change detection uses the normalized form.

Net effect: a comment-only or blank-line edit produces the same hash → entity skipped → no entry in `changed_code_ids` → no spurious `flag_stale_knowledge` run. Semantic changes (`a + b` → `a * b`) still hash differently and update normally.
