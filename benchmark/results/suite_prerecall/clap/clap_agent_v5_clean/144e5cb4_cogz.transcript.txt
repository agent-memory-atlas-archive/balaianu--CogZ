## What was wrong

`Command::ignore_errors(true)` is a global setting that propagates to subcommands. When a subcommand's parser produced an error, `parse_subcommand` swallowed **every** error — including `DisplayHelp`/`DisplayVersion`, which aren't user errors at all (they're stdout-bound informational output, `use_stderr() == false`). So `test sub --help` silently returned `Ok` and the help was never shown.

The same bug was already fixed at the top level in 4.3.9 ("`Command::ignore_errors` no longer masks help/version") via the `error.use_stderr()` check in `Command::_do_parse` — this change extends that convention down through the subcommand boundary.

## The change — `clap_builder/src/parser/parser.rs:747`

```rust
if let Err(error) = p.get_matches_with(&mut sc_matcher, raw_args, args_cursor) {
-    if partial_parsing_enabled {
+    if partial_parsing_enabled && error.use_stderr() {
```

Now stderr-bound parse errors are still swallowed for partial parsing, while help/version propagate up to the caller.
