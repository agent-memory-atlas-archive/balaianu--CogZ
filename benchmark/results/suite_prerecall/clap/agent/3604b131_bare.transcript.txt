## What I changed

`clap_builder/src/parser/parser.rs` — in the `--` (escape) handling inside `Parser::parse`:

Before, when `--` appeared while not in a hyphen-value state, the parser unconditionally set `trailing_values = true`, forcing every following token into the first positional arg. Now it first checks whether the positional arg at `pos_counter` has `--` as its `value_terminator`; if so, the `--` is consumed by that terminator instead of forcing trailing-values mode.

```rust
} else if self
    .cmd
    .get_keymap()
    .get(&pos_counter)
    .map(|arg| {
        arg.get_value_terminator()
            .map_or(false, |t| t.as_str() == "--")
    })
    .unwrap_or_default()
{
    // The value terminator consumes `--`
    continue;
} else {
    // ... set trailing_values
}
```

## Behavior

- `program -- ls -l` (positional with `value_terminator("--")`): `--` is consumed, `ls` and `-l` continue parsing as `cmd1`'s values → `cmd1=[ls,-l]`, `cmd2=[]` — matching `escape_as_value_terminator_with_empty_list` rather than forcing global trailing mode.
- Mid-stream `--` (e.g. `prog find -type f -- /home/clap`): still terminates the collecting arg via the existing `Pos` + `check_terminator` path → `value_terminator_restores_escaping_disabled_by_allow_hyphen_values` unaffected.
- `--` with no `--`-terminated positional, or a non-`--` terminator: unchanged trailing-values behavior.
